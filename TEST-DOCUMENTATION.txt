PURPOSE: Verifies the Zod validation schemas in lib/schemas.ts that gate all
         work order form submissions.  Three schema layers are tested:
           - Time24HourSchema / DateDMYSchema  (field-level primitives)
           - getBaseSchema()                   (shared fields for all roles)
           - getAdminSchema()                  (admin submission rules)
           - getCaptainSchema()                (captain submission rules)
────────────────────────────────────────────────────────────────────────────────

  Time24HourSchema
  ├── accepts valid 24-hour times
  │     "00:00", "12:30", "23:59", "09:05" all pass.
  │
  └── rejects invalid 24-hour times
        "25:00", "24:00", "12:60", "9:30" (missing leading zero),
        "12:5", and "" all throw.

  DateDMYSchema
  ├── accepts valid dd/mm/yyyy dates
  │     "15/03/2025", "01/01/2020", "31/12/2024" all pass.
  │
  ├── rejects invalid format
  │     ISO format "2025-03-15" and US format "01-01-2025" throw.
  │     Partial dates like "1/1/2025" (no zero-padding) throw.
  │
  └── rejects non-existent dates
        "30/02/2025" (Feb 30) and "31/04/2025" (Apr 31) throw.

  getBaseSchema  (shared fields present in both admin and captain schemas)
  ├── accepts minimal optional data
  │     Empty object {} passes; defaults are applied.
  │
  ├── coerces decimal-like values to numbers
  │     Prisma returns Decimal objects; schema converts "100.50" → 100.5.
  │
  └── defaults efectivo and transferir to false
        Payment method checkboxes default to unchecked.

  getAdminSchema  (full order creation/edit)
  ├── accepts valid admin data
  │     Full valid payload including nombre, email, fechaEmbarque, etc. passes.
  │
  ├── requires nombre
  │     Empty nombre string throws.
  │
  ├── requires valid email
  │     "invalid" (no @domain) throws.
  │
  ├── requires horaEmbarque in HH:mm format
  │     "9:30" (missing leading zero) throws; "09:30" passes.
  │
  └── constrains pasajeros between 1 and 6
        0 and 7 throw; 1 and 6 pass.

  getCaptainSchema  (post-trip expense/payment entry)
  ├── accepts minimal captain data with no saldo or extras
  │     Just nombre + apellido is sufficient when no money is owed.
  │
  ├── requires payment method when saldoCliente > 0
  │     If balance > 0, either efectivo or transferir must be true.
  │     Both false throws "Elige un método de pago para el saldo".
  │
  ├── requires pagoRecibo when saldoCliente > 0
  │     Balance > 0 with pagoRecibo = 0 throws "El monto del recibo es requerido".
  │
  ├── requires payment method when horasExtras > 0
  │     Extra hours recorded but no payment method throws
  │     "Elige un método de pago para horas extras".
  │

  useFinancialCalculations > totalClienteCost = precioAcordado + cargoExtra + gastoVarios
